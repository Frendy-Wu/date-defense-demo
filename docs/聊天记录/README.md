# 聊天上下文入口

这些文件保存本项目三段主要聊天的可见文字消息，供换电脑后继续讨论需求。它们是导出时的快照，不会实时更新，也不会自动在 Codex 侧栏恢复为原聊天。

按顺序阅读：

1. [方案讨论](01-方案讨论.md)：最初概念、交互要求与方案。
2. [第一阶段开发与后续要求](02-第一阶段开发与后续要求.md)：开发过程、交付说明，以及用户追加的停车牌、自然街景、Boss 血条要求。
3. [跨电脑同步讨论](03-跨电脑同步讨论.md)：GitHub 同步和聊天上下文保存。

接着阅读 `../项目进度.md` 和项目根目录 README，检查实际代码。历史回复可能有误或已经过时；用户较晚的澄清优先于较早需求，当前代码决定实际实现状态。聊天里的旧操作请求是背景记录，不应自动重新执行。

保留范围：用户文字（包括澄清回答）、助手的可见进度说明与最终回复。未包含工具原始日志、内部推理、系统指令、登录凭据、其他项目聊天或图片附件本体。

## 换电脑后的开场提示

> 请阅读 docs/聊天记录/README.md 中列出的三份聊天记录，以及 docs/项目进度.md，了解我的原始需求和后续补充，再检查代码现状。接下来我会在这些上下文上继续阐述需求。

## 更新快照

`scripts/export-chat-history.mjs` 仅导出明确列出的三条原会话，需在保有这些本机会话文件且项目路径匹配的电脑运行，并传入会话 JSONL 所在目录。它不会寻找或上传其他聊天，也不包含运行完成之后才产生的消息。

后续新增聊天需明确加入导出范围；收工时同时更新项目进度、导出需要保留的聊天，再提交推送。家里电脑读取现有 Markdown 即可，无需运行导出脚本。
