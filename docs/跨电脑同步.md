# 跨电脑同步

本项目仓库：https://github.com/Frendy-Wu/date-defense-demo 。主分支为 `main`。

最省事的方式：打开仓库根目录 `回家继续开发-复制这份提示词.txt`，将全文复制到家里的 Codex。首次下载前也可以直接在 GitHub 仓库网页打开这份文件。

## 首次上传

1. 登录 GitHub，创建私有仓库（例如 `date-defense-demo`）。不要勾选自动添加 README、.gitignore 或许可证，保留空仓库。
2. 将仓库的 HTTPS 地址提供给当前 Codex 聊天，例如 `https://github.com/你的用户名/date-defense-demo.git`。
3. 首次提交需要 Git 作者姓名和邮箱。可使用 GitHub 设置中提供的 noreply 邮箱来保护个人邮箱。
4. 由 Codex 检查待提交内容、配置远端、创建提交并推送；如出现 GitHub 登录提示，在浏览器中自己完成登录。不要在聊天中粘贴密码或访问令牌。

`node_modules/`、`dist/`、测试输出和本地环境变量文件已排除。GitHub 不会保存没有提交并推送的改动，也不会保存项目目录以外的文件或聊天。

## 家里电脑首次准备

1. 安装 Git、符合 README 要求的 Node.js 和 Codex。
2. 在希望存放项目的位置克隆仓库（将下面地址替换为真实地址）：

```powershell
git clone https://github.com/Frendy-Wu/date-defense-demo.git
cd date-defense-demo
npm ci
npm run dev
```

3. 在 Codex 中打开下载得到的项目文件夹，新建聊天并输入：

> 请先阅读 docs/聊天记录/README.md 中列出的三份聊天快照、docs/项目进度.md、README.md 和 docs/方案规划.md，检查代码与 Git 状态，了解我的原始需求和目前实现，再按我的下一条要求继续开发。

仓库中的聊天快照用于提供上下文，不会自动恢复 Codex 侧栏里的原聊天。它们只包含导出时已有的可见文字；新消息需要再次导出、提交和推送。

项目可以放在不同磁盘或目录，不要求两台电脑路径相同。依赖需要在每台电脑分别安装。

## 日常切换

开始前，在工作区没有待处理改动时运行 `git pull --ff-only`。如果提示本地有改动、分支分叉或冲突，让 Codex 检查后处理，不要强制覆盖。

结束时可告诉 Codex：

> 请更新项目进度文档，检查本次需要同步的文件，提交并推送到 GitHub，确认推送成功。

两台电脑尽量轮流修改，换电脑前完成推送。新增或变化依赖后，在另一台电脑拉取完成再运行 `npm ci`。
